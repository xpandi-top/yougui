# 实现范围与对 PRD 的调整（v0.1）

依据：`有归_完整交付包_v1.2/家庭收纳管理_PRD.md`（v1.2）、`页面设计说明.md`、`icons/使用说明.md`，以及 SMALL-APP-ARCHITECTURE。
本文记录 v0.1 **做了什么、和 PRD 哪里不一样、为什么**。这些都是可以再讨论的设计决策，改动时同步更新本文。

## 1. 主要调整（ADR 级）

### ADR-101 本地优先，云端可选（替代 PRD ADR-002「D1 为权威」）

| | PRD v1.2 | v0.1 实现 |
|---|---|---|
| 权威数据 | D1；IndexedDB 只是缓存与草稿 | **本机 IndexedDB**；D1 是可选的同步副本 |
| 离线 | 只能录草稿，不扣库存、不分配标签 | 全部功能可用 |
| 冲突 | 版本号检测，不以最后写入覆盖 | 保留：记录级 `baseVer` 乐观并发，冲突进入复核列表 |

**原因**：本次要求「local 可用，联网也可以用」；SMALL-APP-ARCHITECTURE 第一原则是客户端优先、云端只做跨设备的事；P0 是单用户家庭，本地权威能让不部署任何后端的人也能完整使用。
**代价**：多设备同时改同一条记录需要人工复核；数量字段是整条记录覆盖，不是增量合并（见 ISSUES I-03）。

### ADR-102 家庭同步密钥代替账号登录

PRD 要求 P0 有可验证登录身份。v0.1 用「家庭同步密钥」：服务端生成 256 bit 随机密钥，只存 SHA-256，每个请求 Bearer 校验；可设 `SETUP_SECRET` 防止陌生人在你的服务上创建家庭。
**原因**：单用户家庭不需要账户体系；自部署服务不想维护 OAuth。
**后续**：P1 家庭成员（owner/editor/viewer）时引入真正的身份（Google 登录或 Passkey）并做按成员令牌，见 ISSUES I-05。

### ADR-103 附件上传简化

PRD：浏览器 → Worker 流式上传 → R2，UploadSession 表、operation_id 幂等、校验后激活。
v0.1：文件先完整保存在本机（离线可用），同步时 `PUT /v1/files/:attachmentId` 整体上传（≤20 MiB），Worker 校验 MIME 白名单、文件头嗅探、大小、配额、可选 SHA-256；按「附件 id + checksum」幂等，重复上传不重复计容量；附件记录在文件成功后才标 `remote` 并推送。
没有独立 UploadSession 表；R2 成功但记录没推上去的孤儿文件由每日 Cron 在 24 小时后清理（对应 B07）。

### ADR-104 实体与库存合并

PRD 把具体实物（Entity）和批量库存（Stock + ItemType）分开。v0.1 统一为 **Entity**：
`quantity = null` 是独立实物/不追踪；`quantity ≥ 0` 是批量库存；同型号在多处 = 多条 Entity 共享 `typeId`，商品码挂在 `ItemType`。
**原因**：界面上 PRD 也统一称「物品」；一张表让路径、搜索、移动、附件、标签都只处理一种对象。部分数量移动会在目标处并入或新建同型号库存，满足「来源减少与目标增加原子完成」。附件关联 `targetKind` 预留了 `type`（型号共用说明书），界面暂只关联实体。

### ADR-105 标签 token 在本机生成

PRD：服务端生成不重复 token。v0.1：本机用 `crypto.getRandomValues` 生成 16 位 token（≈80 bit，不可预测）与 6 位短编号（31⁶ ≈ 8.9 亿，本机去重）。扫码以 token 为准，短编号只用于手输与核对，不作为授权凭据。离线也能生成并打印标签。

### ADR-106 打印走浏览器

PRD：生成实际尺寸 PDF 与 300 dpi PNG。v0.1：按毫米 CSS 布局 + `@page`，「每张一页」（标签机）或「A4 排版」，通过系统打印或「存为 PDF」导入厂商 App。未单独导出 PNG。打印成功与否仍需扫描样张确认。

## 6. v0.2 接入房间图标库（交付包「含房间图标库」）

依据 `room-icons/使用说明.md`。

| 交付包建议 | 实现 | 说明 |
|---|---|---|
| 位置实体增加可选 `room_icon_key`，存 `rooms-*` 稳定 id | 复用已有的 `Entity.iconKey` 存 `rooms-*` | 物品与位置共用一个图标字段，不需要数据迁移；id 自带命名空间，不会混淆 |
| 无可识别 id 时回退 `ui-room` | ✅ | |
| 图标作为前端静态资源，不进 R2、不占附件额度 | ✅ | `assets/icons/rooms.json` 随版本打包，内嵌 SVG（currentColor） |
| 房间图标不限制层级、不决定分类 | ✅ | 子位置（柜、抽屉）也可以用物品图标库里的收纳图标，选择器分「房间 / 物品」两页 |
| 选中态不只靠颜色 | ✅ | 选择器用边框 + `aria-pressed`；初始设置的房间 Chip 用实心样式 + ✓ |

设计决策：
- **房间也可以用照片**：位置与物品共用封面机制（`coverId` 指向照片附件）。显示优先级：照片 → 图标 → `ui-room`。取消封面只清引用，照片保留在该房间的「随物档案」里。首页房间卡片有照片时显示照片横幅。
- **按名称推荐图标**：新建房间/子位置时，按名称给出默认图标（如「主卫」→ 卫生间、「储物柜」→ 柜子），对话框里可见、可改。只用于新建时的默认值，不回头推断已有数据（符合图标说明「避免靠名称推断」的迁移原则）。
- **初始设置**：预设房间列表改为来自房间图标库（常用 12 个，「更多房间」展开全部 24 个），建房时直接写入对应 `rooms-*`。
- **命名调整**：图标库区分「浴室」（bathroom）与「卫生间」（powder），文案随之调整；原 `room.kids` 改为 `room.child`。

## 7. v0.3 联网查商品名

PRD v1.2 写明「不承诺联网自动获取商品名称」。v0.3 增加尽力而为的查询，作为可关闭的设置项（默认开启）：

- 免费来源调研（2026-10）：Open Facts 系不限量但只收食品/日化/宠物用品；UPCitemdb 免费试用 100 次/天、无需注册、但 CORS 只放行自家域名；upcdatabase.org 免费 100 次/天需注册；EAN-Search、Barcode Spider、Go-UPC 无免费档。没有比 UPCitemdb 更宽裕的通用免费库，因此采用「Open Facts 直连 → Worker 代理 UPCitemdb（+ 可选 upcdatabase）→ D1 缓存」。
- 查询结果只是建议：自动填入空的名称/分类，用户改过就不覆盖；保存前可修改。
- 隐私：只发送商品码；关闭设置后不发任何请求。
