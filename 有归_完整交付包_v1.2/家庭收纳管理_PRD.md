# 家庭收纳管理 PWA · 产品需求文档

版本：1.2 · 日期：2026-10-13 · 工作名：有归 Homebase

## 1. 产品目标与需求依据
让家庭成员知道物品在哪里，并以极少操作记录物品的放入、取出和移动。新增无纸化目标：将照片、购买凭证、说明书等统一保存或引用，并关联对应物品；独立数字档案库为 P1 扩展，收纳仍是核心。iPhone Safari 优先，可添加至主屏幕，无需 App Store。依据本次明确需求和可读取的原对话；原对话未明确的实现细节在本文标作“设计决策”，不作为历史已确认事实。

核心原则：自由层级；任何物品可启用容器功能；先登记后完善；数量可选；普通扫码默认、连续扫码提高整理效率；搜索显示完整路径；识别成功与库存提交成功明确分开。

## 2. 用户与使用场景
- 初次整理：创建书房 → 打印空白标签 → 扫码绑定配件盒 → 连续添加名称或扫描商品码。
- 日常寻找：搜索 HDMI → 查看完整路径 → 找到后取出或移动。
- 批量搬运：选择目标车库 → 扫描收纳盒 → 整盒移动，内部物品的路径随之改变。
- 盘点：限定位置 → 输入实际数量或扫描 → 复核差异 → 确认调整。
第一阶段为单用户家庭空间；第二阶段增加家庭成员、邀请和协作。

## 3. 范围与优先级
| 优先级 | 交付功能 | 明确边界 |
|---|---|---|
| P0 第一阶段 | 房间 QR；自由层级；物品容器开关；普通扫码；连续入库/取出/移动/盘点；UPC-A、EAN-13、EAN-8 与自定义 QR；预生成空白码与绑定；批量标签导出/打印；极简与连续创建；可选数量；名称/位置搜索；完整路径；移动与数量调整；日志与纠错；基本离线草稿；R2 文件存储/D1 元数据；统一附件、独立附件、多对象关联、外链；图片优化；权限与上传可靠性 | 商品信息可手工填写，不依赖商品数据库；打印采用 PDF/图片与系统打印；不承诺所有蓝牙标签机直连 |
| P1 第二阶段 | 家庭共享、成员权限与冲突处理；分类筛选；照片辅助识别/浏览；最近访问；位置待确认；数据导出与恢复增强；经验证的厂商打印适配；缩略图、Google Drive Picker、数字档案与附件搜索、完整导出/备份/恢复验证 | “按照片查找”先为照片浏览，自动视觉检索另行验证 |
| P2 后续 | AI 自然语言搜索、自动分类、智能补货、图像语义检索、跨家庭管理；OneDrive、OCR/购买信息提取、保修提醒、跨云盘迁移、失效链接检测 | 不阻塞基础收纳 |
设计决策：照片上传、备注和简单分类字段在 P0 可编辑，但分类筛选属于 P1。首页最近操作可由 P0 日志派生；最近访问为 P1。未分配位置为 P0。

## 4. 统一对象与数据规则
| 对象 | 核心字段 | 约束 |
|---|---|---|
| 家庭空间 Household | id、名称、owner | P0 单一所有者，所有数据带 household_id |
| 实体 Entity | id、名称、kind（位置/物品）、parent_id、can_contain、item_type_id?、cover_attachment_id?、备注?、version、状态 | 名称必填；位置可空；单父节点；房间也是位置实体 |
| 物品类型 ItemType | id、名称、规格、单位、条码列表 | 描述型号，不代表唯一实物 |
| 位置库存 Stock | id、type_id、location_id?、tracking、quantity?、version | 同型号可分布多个位置；不追踪时 quantity=null，不能显示为 0 |
| 附件 Attachment | 名称、type、provider、object_key/file_id/url、MIME、大小、状态、version | 独立存在，D1 仅存元数据，文件默认 R2 |
| 附件关联 AttachmentLink | attachment_id、target_kind、target_id、household_id | 多对多，支持实体、位置库存、型号；解除关联不删文件 |
| 标签 Label | 随机 token、短编号、状态、entity_id? | 空白/已绑定/停用；一个标签只绑定一个实体；实体可有多个标签 |
| 操作 Operation | idempotency_key、类型、来源/目标、数量、操作者、时间、前后值、提交状态 | 批次带 batch_id；服务端事务提交；日志不可静默覆盖 |

具体实物（电钻、工具箱）使用 Entity；同型号批量消耗品（电池）使用 Stock。界面统一称“物品”，详细设置才区分逐件与批量管理。启用容器时必须对应一个具体实体；数量为 5 的同型号箱子不能整体变成一个容器，需先选择/建立具体箱子。

层级不得形成环，禁止移动至自身或后代；不固定业务层级上限，界面折叠长路径但支持展开完整路径。删除有子项的位置或关闭有子项的容器前，必须先移动内容。整盒移动只更新盒子的父节点，后代路径动态计算，禁止重复计算后代库存。

数量追踪默认关闭。开启时要求填写当前实际数量（非负整数，P0 单位不可小数）；关闭需确认丢失数量精度并留日志。独立实物按位置与在库/已取出状态管理；不以“-1”表示移除独立实物。未追踪的批量物品取出时确认“全部取出”或先开启数量，不能假装知道剩余数量。

## 5. 创建与位置浏览
名称是唯一必填信息；从位置页面创建自动继承位置；全局创建默认未分配。展开可填照片、型号、分类、数量、备注、容器开关、绑定标签。数量追踪开关默认关闭。

连续创建保存后清空名称、保持位置和键盘、显示已添加列表；提供撤销。简单名称规范化提示相似记录，允许继续创建，绝不强制合并。条码相同意味着同型号候选，不意味着同一实物。

位置页含面包屑、子位置/容器、直接物品；“当前层级/含子层级”切换；添加物品、创建子位置、扫码入口。搜索默认全家，进入位置后可限定范围。物品结果显示名称、数量或“不追踪”、完整路径、查看/取出/移动。空结果提供清空筛选和创建入口。未分配结果显示明确文字，不能伪造路径。

## 6. 标签与条码
房间 QR 打开对应房间；容器 QR 打开内容；物品 QR 打开具体实物。自定义 QR 采用应用 HTTPS 深链接加随机 token，短编号用于手输和打印；编号不能作为授权凭据，服务端始终校验家庭访问权。

UPC/EAN 识别商品型号。保留前导零、校验校验位；UPC-A 与前导 0 的 EAN-13 规范化以避免重复型号，但保留原始码。一个型号可有多个条码；同一家庭内一个标准化商品码关联一个型号。多个位置/实物匹配时必须选择来源。未知商品码进入极简创建并记住关联；不承诺联网自动获取商品名称。

空白码：输入张数 → 服务端生成不重复 token → 选择纸张尺寸 → 预览 → 导出 PDF/PNG 或打印 → 扫描空码 → 绑定已有实体/创建实体/创建位置 → 原子保存。绑定前不强制创建实体。默认一张码一次绑定；重新绑定需显示旧目标、确认、留日志，停用旧标签以防误导。复制打印同一标签仍指向同一实体，重新打印不产生新实体。

批量标签任务显示编号、绑定状态、纸张和导出状态；取消打印不撤销已经生成的空白标签；失败可重试相同任务，避免重复生成。打印内容可选名称/路径/短编号；空白码只含短编号和 QR。QR 必须保留四模块静区、高反差、不拉伸。建议先验证 40×30 mm，再评估 30×20 mm；尺寸是待实机校准建议，不是硬件兼容承诺。

## 7. 扫码状态机与行为矩阵
状态：未开始 → 请求权限 → 扫描 → 解析 → 需补充信息/待提交 → 提交中 → 已保存；各阶段可进入错误与可恢复状态。单次扫码识别后暂停；连续模式保留预览，弹出需选择的表单时暂停识别。

| 对象 | 普通 | 入库 | 取出 | 移动 | 盘点 |
|---|---|---|---|---|---|
| 房间/容器 QR | 打开内容 | 设置目标 | 设置来源 | 设置目标 | 设置范围 |
| 实物 QR | 打开详情 | 放入目标，已在目标提示 | 记录取出 | 加入移动清单 | 标记已见；同一码只算一次 |
| UPC/EAN | 型号与位置列表 | 型号库存增加 | 选择来源后减少 | 选择来源与数量 | 输入实际数量或计件扫描 |
| 空白 QR | 创建/绑定 | 暂停绑定后继续 | 提示不可取出 | 暂停绑定后继续 | 暂停，绑定后纳入 |
| 未知商品码 | 极简创建 | 创建后继续 | 选择已有或取消 | 选择已有来源，不凭空移动 | 创建为新增差异 |
| 外部/无效 QR | 显示不可识别，手输 | 同左 | 同左 | 同左 | 同左 |

连续模式先选择操作，再扫描/选择位置，随后扫描物品。扫描另一个容器时先问“更换目标”还是“作为待移动物品”，避免容器双重身份误判。存在待提交清单时切换位置或模式必须确认处理旧清单，禁止静默改写。

同一码留在镜头内只触发一次，离开后重新进入或点击“再加一个”才能重复计件；建议 1.5 秒去抖并实机调优。实物 QR 重扫提示已加入；商品码重扫可显式 +1。声音可选，视觉反馈必须存在，不依赖 iPhone 振动。

## 8. 四种库存操作
入库：目标 → 物品 → 数量（追踪时默认 1）→ 清单 → 确认。已有实物在另一位置应引导移动，不能复制实物。全新实物可直接放入。

取出：来源 → 物品 → 数量/全部 → 确认。数量不得超库存；取出后状态为已取出/离开库存，可重新入库，保留原位置历史。删除错误记录另设操作，明确“删除记录”与“取出实物”。

移动：目标 → 物品 → 来源消歧 → 数量 → 确认。批量库存支持部分移动，来源减少与目标增加必须原子完成；独立实物和容器只能整体移动。来源与目标相同提示无需操作。

盘点：指定是否含子层级 → 建立库存快照 → 扫描或输入实际值 → 差异复核 → 保存调整。未扫描不自动归零；需用户明确标记缺失。未知数量允许只确认“已见”而不生成数值。若盘点期间库存变化，提交时重新复核受影响条目。不得把扫描次数直接当作包装内数量，首次关联询问计数单位。

单件操作保存后显示可撤销；撤销以反向操作记录，若依赖状态已变化则阻止并引导修正。批量操作先暂存，最后统一提交；建议 P0 每批最多 100 条、超限拆批（设计决策）。成功提示带操作对象和数量，失败保持清单。取消尚未提交的批次不修改库存。

## 9. 异常与恢复
| 异常 | 用户看到 | 系统规则/出口 |
|---|---|---|
| 相机拒绝/不可用 | 权限说明、重试、手输码/名称搜索 | 不循环弹权限，不阻塞手工操作 |
| 暗光/反光/损坏 | 调整光线、手输短编号 | 补打原标签；不依赖手电 API |
| 码已绑定/他人家庭码 | 已绑定对象或无访问权 | 不自动抢绑，不泄漏其他家庭信息 |
| 同型号多位置 | 来源列表与完整路径 | 必须选择，不猜测来源 |
| 库存不足/版本变化 | 标注冲突行与最新值 | 整批不写入，修正后重试 |
| 网络断开/响应未知 | 草稿待提交/正在核对 | 保留幂等键，查询提交结果，禁止重复扣减 |
| 退出/切后台 | 暂停扫描、保留草稿 | 恢复时重新请求流；停止摄像轨道 |
| 层级成环/容器非空 | 原因与内容列表 | 拒绝操作，提供先移动内容入口 |
| 盘点范围不完整 | 未核对列表 | 不推断缺失，明确复核 |
| 打印缺纸/比例错误 | 重印/导出/校准 | 打印对话框关闭不等于成功；用户确认样张 |
| 本地存储被清理 | 重新登录并同步 | 服务端为正式库存来源，本地草稿不保证永久保留 |

## 10. iPhone PWA 与兼容性
P0 建议验证 iOS 18 及以上 Safari 和主屏幕模式；这是拟定支持范围，发布前根据实机结果冻结。桌面/Android 提供基本浏览与手工录入，不承诺同等硬件能力。

摄像头必须在 HTTPS 安全上下文和用户授权下调用 getUserMedia，优先后置相机，video 使用 playsinline；仅请求视频。BarcodeDetector 非普遍可用，必须能力检测并提供经验证的 JS/WASM UPC/EAN/QR 解码回退。镜头切换、旋转、锁屏恢复、权限撤销需实机验证。不能用模拟扫描证明相机兼容性。[MDN 摄像头](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) · [BarcodeDetector](https://developer.mozilla.org/en-US/docs/Web/API/BarcodeDetector)

提供 manifest、图标、standalone、safe-area、Service Worker 版本更新。安装通过 Safari 分享菜单“添加到主屏幕”，不依赖浏览器自动安装提示；具体菜单随版本变化。[Apple 安装指引](https://support.apple.com/en-mide/guide/iphone/iphea86e5236/27/ios/27)

离线 P0 缓存应用壳与最近读取数据，允许录入草稿，不显示已同步；离线不进行正式扣库存和全局唯一标签分配。恢复联网后由用户复核并提交，冲突不以最后写入覆盖。P1 再考虑自动队列同步。iOS 可能回收存储与后台进程，不依赖后台持续扫码或同步。

打印：P0 生成实际尺寸 PDF、300 dpi PNG；有 AirPrint 的设备走系统打印，否则保存文件到厂商 App。多数小型蓝牙标签机不能假定 Safari 直接连接；Web Bluetooth 非普遍支持，不作为 P0 前提。选定型号必须验证厂商 App 是否可导入 PDF/图片、纸宽与边距；无法导入时用兼容设备或电脑打印。Safari 不能读取打印机成功状态。[MDN Web Bluetooth](https://developer.mozilla.org/en-US/docs/Web/API/Web_Bluetooth_API) · [Apple AirPrint](https://support.apple.com/en-us/109349)

## 11. 页面架构与设计约束
底部导航：首页 / 位置 / 扫码 / 物品 / 更多。主要页面：首次建立家庭、首页、全局搜索、位置树、位置详情、物品详情、极简/连续创建、扫码（普通/连续）、来源与目标选择、待提交清单、盘点差异、空码绑定、标签中心、打印预览、日志、设置；P1 增加家庭成员和待整理。

视觉方向：暖白背景、深松绿主色、纸张卡片、少量橙色提醒；中文系统字体；iPhone 390–430 px 优先，同时覆盖 375 px。正文 16 px，辅助文字至少 12 px，交互目标至少 44×44 px。状态同时使用文字与颜色；尊重动态字号与减少动画设置；长路径换行，禁止仅截断重要位置。

键盘弹出时保持提交按钮可达；底部导航预留安全区；扫码界面优先暗色，清晰显示当前模式、位置及未提交数量；底部操作单手可达。

## 12. 安全、性能与验收
库存和标签 API 均验证所属家庭；HTTPS；随机不可预测标签 token；QR 不嵌入物品名称和私人地址；日志记录必要行为，照片不默认公开；账户删除提供数据导出和明确清理范围。

目标（待压测）：1 万物品、10 层层级下名称搜索 P95 ≤1 秒；扫描解码在正常光线下中位数 ≤1 秒；100 条提交 ≤3 秒（正常网络）；冷启动首屏 ≤3 秒。统计创建耗时、扫码失败率、提交失败率、搜索后成功定位反馈；摄像画面不上传用于分析。

| 编号 | P0 验收场景 | 预期结果 |
|---|---|---|
| A01 | 只输入名称保存 | 成功、位置可未分配、数量 null、可撤销 |
| A02 | 书房/柜/盒/线搜索 | 结果含完整路径；搬盒后路径立即更新 |
| A03 | 背包开启容器后添加物品，再关闭 | 非空拒绝关闭；无丢失记录 |
| A04 | 空码首次绑定与重复绑定 | 首次成功；重复显示目标并阻止抢绑 |
| A05 | 同 EAN 分布两位置，移动部分数量 | 必选来源，来源目标合计守恒 |
| A06 | 连续 20 次扫描、镜头停留同一码 | 停留不重复；清单可改、确认前库存不变 |
| A07 | 提交后断网重试同批次 | 至多执行一次，正确恢复结果 |
| A08 | 取出超过库存/移动到后代 | 阻止且可修正，数据不变 |
| A09 | 盘点未扫描记录 | 不自动清零；差异复核后才调整 |
| A10 | 权限拒绝/锁屏/切后台 | 手工入口可用，恢复可重启，退出释放相机 |
| A11 | 40×30 mm 打印样张扫码 | 实际尺寸与静区合格；连续读取 20 张均正确 |

## 13. 分阶段交付与未决事项

## 15. 统一附件领域模型
照片不再作为孤立 photo_url 存在。Attachment 是家庭空间内独立对象；Entity.cover_attachment_id 引用已关联且可访问的 Photo 附件。Stock 与 ItemType 也可关联附件，以覆盖按位置聚合管理的电池库存与共用型号说明书，防止“有库存但没有独立实体”时无法关联。

| 数据 | 必需/可选字段 | 约束 |
|---|---|---|
| Attachment | id、household_id、name、type_key、provider、status、created_by、created_at、updated_at、version | name 必填；type 可扩展；独立于物品生命周期 |
| 文件引用 | R2 object_key / 云盘 file_id / external_url 三选一 | 不把带时效签名的访问 URL 存成长期引用；文件内容不进入 D1 |
| 文件属性 | original_name、stored_name、mime_type、size_bytes、checksum?、width?、height?、source_size? | URL 来源大小与 MIME 可未知，不伪造；保留原始文件名 |
| 附加属性 | note、thumbnail_key?、optimized、retention_until?、error_code? | 是否压缩显式记录；缩略图仅 P1 |
| AttachmentLink | household_id、attachment_id、target_kind、target_id、created_at | target_kind=entity/stock/item_type；复合唯一，拒绝跨家庭；多态关联需服务端验证目标存在 |
| UploadSession | id、attachment_id、operation_id、expected_size/type、state、expires_at | 上传初始化、完成、重试幂等；配额预留与释放 |

类型基线：Photo、Receipt、Manual、Warranty、Invoice、Maintenance、Document、Link。业务类型与 MIME 分离：Receipt 可以是 JPEG 或 PDF；Link 可以引用 PDF 说明书但不把外部文件视为 R2 文件。provider=r2/external_url/google_drive/onedrive；P0 只开放前两种。

生命周期：draft → uploading → verifying → ready；失败为 failed；删除为 deleting → deleted；URL 元数据可直接校验后 ready。只有 ready 才展示为可用附件。附件无关联也合法，删除物品默认只清除关联，保留附件。删除封面附件/关联时清除对应 cover_attachment_id，回退用户选择图标或默认收纳盒。

P0 未关联附件入口：更多 → 未关联附件（基础列表），可上传、关联或删除，不提供独立档案分类和搜索。P1 数字档案在同一入口升级为全家文件浏览、类型筛选和名称搜索，避免 NEW-005 被错误推迟到 P1。

## 16. 系统架构与上传一致性
| 层级 | 确定技术 | 职责 |
|---|---|---|
| 前端 | React + Vite + TypeScript + MUI | 生产 PWA；MUI 自定义新中式主题；本次单文件原型不是框架实现 |
| 托管 | GitHub Pages | 静态前端；正确设置 Vite base、manifest scope、SW 路径；路由优先 hash 防刷新 404 |
| API | Cloudflare Workers + Hono | 身份/家庭权限、业务校验、上传会话、文件读取、删除协调 |
| 数据 | Cloudflare D1 | 物品、位置、库存、附件元数据、关联、操作版本 |
| 文件 | Cloudflare R2 | 默认私有文件对象与 P1 缩略图 |
| 本地 | IndexedDB | 已授权数据缓存、草稿、待同步操作；非数据权威 |
| 集成 | Google Drive / OneDrive | P1/P2 授权文件引用，不默认为 R2 副本 |
| CI/CD | GitHub Actions | 前端/API 分开构建部署；生产密钥仅部署 secret |

前端经 HTTPS 调用 Worker，Worker 按家庭访问 D1/R2。GitHub Pages 本身不执行 Hono 或保存密钥。前端站点与 API 域不同，应配置精确 origin 白名单、身份令牌验证、必要的 CSRF 策略；CORS 不是授权机制。P0 即使只有家庭所有者，也必须有可验证登录身份，不能仅靠请求中的 household_id。

默认 P0 上传路径（设计决策）：浏览器 → Worker 流式上传 → 私有 R2；API 逐次校验身份、大小、MIME 与家庭配额。P1 可评估短期预签名 PUT 直传，减少代理开销；直传完成后仍须 Worker 验证对象再激活，不能把 URL 发送成功当作文件已保存。预签名链接持有者在时效内可访问，需限时、精确对象与方法，不写日志；浏览器直传还需 R2 CORS。[Cloudflare 预签名 URL](https://developers.cloudflare.com/r2/api/s3/presigned-urls/) · [R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/)

上传协议：
1. 初始化：验证请求与关联目标，生成不透明 attachment_id/object_key，D1 写 UploadSession，返回 upload_id。
2. 客户端处理照片，上传内容；进度区分“准备/优化/上传/确认”，不展示虚假的百分比。
3. Worker 校验签名 MIME/实际文件特征和内容长度，将对象写入隔离状态；校验失败删除临时对象。
4. 完成请求按 operation_id 幂等；验证 R2 对象存在、大小与预期一致，用 D1 批处理写 ready 与关联；成功后才显示已保存。
5. 超时先查询会话状态，再重试同 upload_id；不得创建多个 ready 附件。

D1 与 R2 无跨服务原子事务，采用上传会话、可重试步骤及补偿清理。定时清理超过 24 小时的未完成上传（设计决策，需冻结保留期）；删除临时对象前确认未被 ready 引用，避免清理与完成请求竞态。定期核对 D1 ready 记录与对象，对缺失标记不可用并告警，不静默丢失元数据。

AttachmentStorageProvider 是 Worker 内的提供者接口；客户端只调用受控 API，不持有 R2 凭据。生产接口在用户建议基础上补充 context（授权家庭）、operation_id、contentType/size，并提供 upload/complete/getAccessUrl/delete；getAccessUrl 只返回短期地址或鉴权代理端点。ExternalReferenceProvider 单独负责引用校验与解析，不伪装为文件上传。后续云盘提供者通过 capability 描述能否上传、读取或删除，引用外部文件不意味着有权删源文件。

## 17. 文件处理、限制与可靠性
| 内容 | P0 处理 | 预览/降级 |
|---|---|---|
| 普通 Photo | 浏览器保持宽高比，长边目标 1600 px，输出 JPEG/WebP；修正方向并移除不必要 EXIF；小图不放大 | 展示标准优化图；独立缩略图生成属 P1 |
| Receipt/Invoice/Warranty/Manual/Document/Maintenance | 默认保留原文件与原格式，图片也不有损压缩 | PDF/图片原文件预览，文字不清晰时下载原件 |
| HEIC/HEIF | 检测浏览器能否解码；若可转换需明确只保留优化图；不支持时提供选择 JPEG/PNG 或作为原始文档保存 | 不声称所有 Safari 均能 canvas 解码；真机验证大图内存 |
| 外部 URL | 仅存引用，不自动抓取/缓存文件 | 外部安全打开，不依赖跨域 iframe 可预览 |

P0 建议参数（待确认，不是平台上限）：单文件 ≤20 MiB；单次最多 10 个；家庭配额初始 5 GiB 可配置。文件允许 JPEG/PNG/WebP/HEIC/HEIF/PDF；PDF 以外办公文档后续扩展；拒绝 HTML、SVG、可执行文件与 MIME 伪装。大小以服务端实收值为准；提前检查原始文件大小、优化图大小与剩余配额。容量达到上限时禁止新上传，但允许查看、下载与删除。

Photo 压缩前提示“保存优化图，原图不会另外保留”，原图默认不上传；需要保留原件的用户可选择 Document 或凭证类型。不得将所有照片格式收据套用 Photo 压缩规则。图片失败不阻塞纯名称创建；附件后补，物品成功与附件失败分别提示。

上传 UI：选文件 → 填名称/类型/备注 → 选择 0..N 关联目标 → 展示优化/原件策略 → 上传进度 → ready。取消终止当前请求并标记会话待清理；失败保留可重试表单，刷新后无法恢复本地 File 时要求重选，不能声称文件已永久缓存。离线允许附件元数据草稿；大文件只在用户同意且空间足够时保存在 IndexedDB，否则提示联网后重选，不依赖后台上传。

## 18. 页面与附件管理行为
物品详情新增封面及附件区域，提供拍照/选择文件/添加链接、预览、下载、编辑名称/类型/备注、管理关联。创建物品可选拍照但不新增必填项；搜索结果使用封面优化图，未设置回退用户选择图标或默认收纳盒。P0 不因缩略图 P1 而阻塞封面展示。

附件详情：名称、类型、来源、原文件名、大小、上传状态、备注、关联对象及完整路径。R2 文件可预览/下载；URL 显示域名与“打开外部资源”，无法保证下载能力。鉴权失效时重新请求访问，不展示永久公共 URL。

关联管理：搜索选择已有对象，允许多个；同一份 Costco 收据关联电池、灯泡、清洁用品。不复制二进制内容。移除其中一条关联仅删除 AttachmentLink；最后一个关联解除后变为独立附件。源物品删除也不自动删文件。

删除分为两个明确动作：
- “从当前物品解除关联”：仅修改当前关联，不要求用户承担其他对象的数据损失。
- “删除附件及文件”：显示关联数量与名称、说明所有关联将受影响，由 owner 执行。P0 单所有者；P1 editor 默认允许上传/编辑/关联/解除关联，viewer 只读，彻底删除和导出限 owner。

删除为可重试过程：确认 → D1 标记 deleting、立即禁止新访问及关联 → 删除 R2 对象/缩略图 → 清理关联和封面 → deleted。R2 删除失败保留 deleting 重试；不误报已删除。已有短期签名 URL 可能直到过期仍有效，因此敏感读取优先鉴权代理；页面提示无法撤销已下载副本。外链或云盘引用的“删除”只删除应用内引用，不删除外部源文件。

P1 数字档案由更多进入：购买凭证、说明书、保修资料、房屋维修、未分类/未关联视图；支持名称/类型搜索、先保存后关联、按关联状态过滤。原型可展示 P1 设计，但入口必须标明阶段，不能混入首版已交付声明。

## 19. 权限、外链与第三方集成
R2 bucket 私有，禁用公开读取；每次初始化上传、完成、预览、下载、编辑、关联、解除关联、删除都验证登录和家庭成员权限。读取同时核查附件属于家庭及 ready 状态，不凭 object_key 直接授权。跨家庭不存在或无权限统一返回安全提示。日志不记录文件内容、令牌或签名 URL；API secret 不进入 GitHub Pages bundle、源码仓库或浏览器存储。

URL P0 仅允许 http/https，拒绝 javascript/data/file 等方案；显示域名、外部来源提示，使用隔离新窗口，不自动 fetch，不将其设为公开。若未来加入服务端抓取/失效检测（P2），须额外处理 SSRF、重定向、内网地址和请求限额。外部资源权限、过期、被移除都不影响本地关联元数据；用户可修正链接。

Google Drive Picker P1：经用户 OAuth 授权选择文件，保存 provider/file_id 与名称等元数据，不默认复制到 R2。最小授权范围、授权撤销、文件删除和 Safari 弹窗/独立模式为验收项。Picker 不自动赋予其他家庭成员源文件访问权；成员无法访问时提示去云盘申请权限，不替用户修改分享设置。[Google Web Picker](https://developers.google.com/workspace/drive/picker/guides/web-picker)

OneDrive P2 遵循同等引用规则。默认删除只解绑引用；跨云盘迁移需逐文件确认源读取和目标写入权限，不能假定来源永远可下载。

## 20. 导出、备份与恢复（P1）
完整 ZIP 包含 schema_version、导出时间、家庭/位置/实体/型号/库存、操作日志、附件元数据、关联表、文件清单与 checksum，以及用户有权导出的 R2 文件。外部链接/Drive/OneDrive 仅包含引用及元数据，清单标记 content_included=false、来源和未纳入原因，不把链接备份描述为文件备份。签名 URL、会话令牌、R2 secret 不导出。

D1 与 R2 备份分别执行，但使用同一 manifest 建立对应关系；通过快照/版本水位和导出期间变更复核建立一致集合，排除 uploading/deleting 项并报告。大包异步生成、可取消、显示状态；下载前重新鉴权，临时导出包限时清理，不走前端全量内存拼 ZIP。

恢复：先校验 manifest/schema/checksum → 模拟导入报告 → 选择创建新家庭或明确映射 → 恢复元数据与文件 → 校验关联和封面 → 用户确认成功。禁止默认覆盖现有库存。外部凭据不恢复，外链可能需重新授权。备份成功须有恢复演练证明，目标建议 RPO≤24h、常规家庭 RTO≤4h（待运维验证，不是既有承诺）。

P2 跨云盘迁移：复制 → 校验 → 切换引用 → 保留旧文件至用户确认；失败回退旧引用。默认不删除源文件。

## 21. 架构决策记录
ADR-001 附件存储策略（已采纳）：R2 默认私有文件存储，D1 仅元数据；统一提供者层，外链为引用；附件独立、多对象关联；Worker 鉴权；支持完整导出。影响：需上传会话与跨服务一致性补偿，不能用 D1 单事务覆盖文件写入。

ADR-002 数据权威来源与离线同步（已采纳）：D1 是家庭业务数据权威，R2 是文件字节来源；IndexedDB 缓存与待同步操作均非最终提交。操作 ID 防重，版本号检测冲突。与原版离线规则兼容：P0 恢复联网后复核提交，P1 再开放自动队列同步；附件无 ready 确认不显示已保存。退出账号清理授权缓存与本地待提交敏感附件，明确提醒未同步内容会丢失。

ADR-003 原件与图片优化（设计决策）：Photo 默认只保留优化图；收据/发票/保修及文档保持原件；用户在保存前可选择类型。缩略图是 P1 衍生资源，不替代原件。这样避免无纸化凭证因通用照片压缩而损失细节。

## 23. v1.2 图标系统与无照片物品
新增 P0 设计要求：页面图标采用统一 24 px SVG 体系；物品支持从内置图标库选择可选 icon_key。当前资产版本包括 32 枚页面图标与 48 枚物品图标，按收纳/数码/工具/衣物/厨卫/文具/出行/家居/健康/生活分组。SVG 作为公共静态前端资源，不进入附件系统或占用 R2 配额。

Entity 与 Stock 增加可选 icon_key。封面照片优先，自选图标次之，未知/缺失 ID 使用默认收纳盒。创建仍仅必填名称，图标可稍后修改。图标的分组不等于物品分类，挑选容器图标不会启用容器功能。取消封面引用后显示图标，但不得删除照片附件。

页面：创建页内嵌图标选择（保留其他未保存输入）；详情页进入图标选择器，支持名称/类别检索、选中预览、保存或取消。图标按钮命中区至少 44 px，配文字或可访问名称；选中态同时提供边框及 aria-pressed。

新增验收：无照片物品创建不选图标可成功；选择图标保存后列表/搜索/详情一致；封面存在时优先显示照片；取消封面不删附件；未知 ID 安全回退；变更图标不改位置、数量、分类或 can_contain。最终仍需 iPhone/VoiceOver 实机验收。
